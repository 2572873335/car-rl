### R1（= B3 复发）★ **一个新的两行几何策略拿到 `FULL = 1.00`，与正例无法区分**

**策略（我本轮设计，plan 未列）**——**没有任何调速技能，`a_speed` 恒 0**，只有一条 lane 规则：

```python
def geom(o, L):                       # 两行；零超车计时、零碰撞规避、零速度决策
    d = o[0] * 2.5                    # delta（米）
    return np.array([0.0,             # a_speed = 0（对等速，纯几何）
                     1.0 if d < 0.30 else -1.0])   # 落后就切内圈，领先就回外圈
```

**实测（leader band 0.15–0.30，与正例同协议；三组 seed × 30 局）**：

| seed0 | 策略 | FULL | ot | 碰撞 | t_overtake |
|---|---|---|---|---|---|
| 123000 | **正例 ckpt** | **1.00** | 1.00 | 0% | 1.62 s |
| 123000 | **`geom`（两行）** | **1.00** | 1.00 | **0%** | 19.37 s |
| 200000 | **正例 ckpt** | **1.00** | 1.00 | 0% | 1.67 s |
| 200000 | **`geom`（两行）** | **1.00** | 1.00 | **0%** | 20.14 s |
| 300000 | **正例 ckpt** | **1.00** | 1.00 | 0% | 1.61 s |
| 300000 | **`geom`（两行）** | **1.00** | 1.00 | **0%** | 19.53 s |

**`FULL` 对两者的取值完全相同（1.00）。** 判据把「两行几何脚本」与正例**排在同一格**。

**可复现**（我独立脚本，从 repo import）：
```bash
cd /home/zy/car_rl/code0919 && uv run python /mnt/c/Users/Administrator/rev2c.py
```

**机制（实测 trace，rev2g/rev2f）**：正例 ckpt 的 lane 时序 = `[(1, 0.0–7.7s), (0, 7.7–30s)]`
——切内圈 ~7.7 s 取得领先后回外圈并保持。`geom` 的时序 = `[(1, 0.0–17.3s), (0, 17.3–30s)]`
——**同样的两步，只是慢一些**。两者的差别**只有「切入要不要判断、切回要不要求时」**，
而 `FULL` 的定义里**没有这两样**：

```python
# _criterion_v3.m_full()（= 仓库 crit_v3_full.py 的 body，逐字节相同）
FULL = 1  ⟺  曾领先(delta>0.3) 且 之后 lane==0 过 且 回外圈后未再落后
```

**任意**「先落后→切内圈→领先→切回外圈」的策略都满足，**与是否真的会超车无关**。
`loiter` 之所以 FULL=0，**只因为它 `lane` 恒 1（从不回外圈）**，
**不是因为它不会超车**。§1.2/§1.3 的结论「`FULL` 解决了 F17（几何买领先）」
**因此不成立**：`FULL` 只加了一个**对已领先者免费**的动作（回外圈），
**没有剔除几何本身**。

**修订要求**：因变量必须引入 **(a) 超车用时上限**（见 §五-推荐），
和/或 **(b) 回外圈后必须回到跟随位（d_des）而非仅「未落后」**，
并**先用退化表证明 `geom` 这类常驻内圈+回外圈策略落带外**。

### R4 ★ `FULL` 会把「套圈后保持领先」误判为「回外圈后又落后」——因变量不是技能的单调量

**实测（规则机作 follower，band 0.15–0.30，30 局，`rev2j`）**：
```
returned_outer = True        : 30/30
held_after_return = False    : 30/30      ← 全部翻掉
max delta 达到 > 2.0（近套圈）: 30/30
⇒ m_full() = 0.00  （30/30）
```
**逐帧 trace（`rev2i`，seed 123000）**：
```
 t=2.0  delta +0.250  lane0=0   (已超越、已回外圈)
 t=4.0  delta +0.939  lane0=0   returned=True   ← 机动完成，且 0 碰撞
 t=8.0  delta +2.270  lane0=0   ← 保持领先、逼近 +L/2
 t=10.0 delta −2.242  lane0=0   held→False      ← **套圈，delta 回绕过 ±L/2**
```
**机制**：`_criterion_v3.py:47-51`
```python
if not np.isnan(self.t_first_ahead):
    if self.lane[0] == 0:
        self.returned_outer = True
    if self.returned_outer and d <= 0.0:      # ← d 是 wrapL 后的值
        self.held_after_return = False
```
`delta` 被 `wrapL` 限在 `±L/2`（**v1 评审 I4 已指出**）。一个**持续领先快一圈**的策略，
其 `delta` 会**回绕为负**，于是被 `d <= 0.0` **误判为「落后」**。

**这是冻结 env 明确防过的事**（`overtake_env.py:229-231`）：
> `NOTE: ahead_flag is NEVER reset - delta wraps at +-L/2 once the faster follower
> laps the leader, which must not count as "losing the lead".`

`FULL` **没有继承这条守卫**。

**后果（决定性）**：`FULL` **不是技能的单调函数**——
- 「超车快、且持续领先到套圈」的**规则机** ⇒ `FULL = 0.00`；
- 「超车慢、浅领先、不套圈」的 **`geom`** ⇒ `FULL = 1.00`。

**判据把更强者判低。** §2 表把规则机标 `FULL=0.00 / 50% 碰撞`归因于「它在本世界不是合格正例」，
**这个归因是错的**——它在**零碰撞**的批次里同样 `FULL=0`（实测 `rev2h`：规则机 vs band 0.15–0.30，
碰撞 **0%**、FULL **0.00**）。**失败原因是套圈回绕，不是「不合格」。**

**修订要求**：`held_after_return` 必须**基于「未被追上」而非「delta 的原始符号」**——
例如用「相对排序是否翻转」或「(s_self − s_other) mod L 是否落在 [0, L/2)」判定，
并**显式记录「已套圈」状态**（冻结 env 的做法可直接借鉴）。

## 三、建议

- **S1（关键）**：因变量改为**复合门**，并用**退化表**证明几何脚本落带外：
  ```
  FULL' = (t_overtake ≤ τ) ∧ (returned_outer) ∧ (held_after_return, 套圈感知) ∧ (collision==0)
  ```
  其中 **τ 有实测分隔依据**：`t_overtake` 上，正例 ckpt **1.6–1.9 s**、
  规则机 **2.2–2.6 s**、而慢几何脚本 `geom` **19.4–20.1 s**（`rev2c`/`rev2h`）。
  **τ ≈ 5 s 即可把「真超车」与「磨蹭到领先」分开**（这是本轮唯一实测出的
  **有分辨力的量**——建议把它写进判据，而不是继续用 `FULL`）。
  **注意**：快几何脚本（`geom_fast`，内圈全油门）`t_overtake ≈ 2.1 s` **仍会通过**，
  故 τ 必须与「回外圈后回到跟随位（d_des）」**联合**使用，单独 τ 不够。
- **S2**：把「回外圈」升级为「**回到跟随位**（`delta ≤ d_des`，如 0.2）+ 保持 T 秒」——
  这样「领先一整圈」不再是「未落后」，而是**明确超了任务语义**。
- **S3**：`held_after_return` 改为**套圈感知**：只有「被对手从后追上（相对排序翻转）」才算落后，
  `delta` 回绕不算（照抄 `overtake_env.py:229-231` 的守卫）。
- **S4**：随机化可再补一层——**给 scripted leader 加真正的行为随机**（正弦/刹车，
  即冻结 env 的 `behaviors`），否则「多种终局」只来自初始条件 2 个标量。
- **S5**：把 `_criterion_v2/v3.py`、`_rolefixed_probe.py` **入库**，
  crit 脚本一律**从仓库 import**（工作树已试做 bootstrap，**但未 commit**），

## 四、对 §5 待评审确认点的逐条答复

**Q1（`FULL` 定义是否恰当；是否该要求回到 d_des）**：
**不恰当（R1/R2/R4）。** 必须：(a) 加套圈感知（R4）；(b) 加碰撞硬门（R2）；
(c) 「回外圈」升级为「回跟随位 d_des」（否则`geom` 仍过，R1）。
