## 裁决：**Reject（须修订后重审）**

**方向正确，交付物不合格。** plan 采用的"任务级判据 + 打破对称性（固定落后起跑）"
方向是对的，§1.2 的三处修正（C1/C2/C3）经我独立复现**全部成立**，
§2 表里的数字也与脚本**逐位复现**（作者没有编造数字）。

但 §10.4 要求的那份**退化反例表本身不成立**：

1. **§2 的"正例"（FROZEN CKPT，win=1.00）是通过一个本项目已公开撤回的适配器 bug
   产生的**——把 gap 修正后，正例从 **1.00 掉到 0.00（40/40 碰撞）**。
   即：**正极是伪影**。用户点名的"退化表是否包含正例"这一问，答案是：
   **表里有正例，但那个正例是假的。**
2. **判据世界没有任何随机源**——`RoleWorld.reset(rng, gap)` **从不使用 rng**。
   对确定性策略，"40 局"是**同一条 rollout 重复 40 次**（实测 unique_delta = 1/40），
   "3 seed 集"也是同一结果。故 plan 的 "≥30 局 3 seed 集" 与 §4 的
   "边界补 seed" 条款**在构造上不可实行**：确定性策略的胜率只能取 **0 或 1**。
3. **一个两行、零博弈技能的策略通过了判据，并且在 thr=2.5 时反超 plan 自己的正例**
   （技能排序被倒置）。这正是用户担心的"从训练目标之外的方式被满足"。
4. **根因是判据的因变量有界饱和**：`delta` 被 `wrapL` 限制在 `±L/2 = ±2.7425`，
   而内圈每圈短 0.94 m ⇒ 任何"切到内圈绕圈"的策略 delta 都单调爬到 ~+L/2 并钉住。
   实测两条轨迹都停在 2.3–2.5 的锯齿上，**"干净 plateau [1.0,2.0]"其实是 wrap 饱和带**，
   它测的是"切得早不早"，不是"超得好不好"。
   故 §2 的"thr=2.5 正例也掉（过严）"**诊断错误**：thr=2.5 掉的是**两者都掉**，
   而 plan 漏报了 loiter 在 2.5 **仍然通过**。

四条都是"**判据投入使用前必须被拦下**"级别。本项目的评审流程前六次都在动手前拦住真问题——
**这一稿的退化表看起来最完整（有正例、有阈值扫描、有 caveat），但它恰恰被同一种
历史 bug（F12 适配器静默失效）污染，且因变量本身选错了量纲。** 修好后再送审（review2）。

## 一、拦截级问题（导致判据作废）

### B1. §2 的**正例（FROZEN CKPT win=1.00）是一个已撤回适配器 bug 的伪影**

**证据链（全部实测）**：

**(a) 判据脚本导入的是被撤回的那个适配器。** 六个 `crit_*.py` 全部写：

```
sys.path.insert(0, "/tmp")
from _ckpt_as_opponent import frozen_layout        # crit_final_table.py:20
```

而 `results/20260920_phaseC_probe/scripts/_ckpt_as_opponent.py:46`（与 `/tmp` 版逐字节相同）：

```python
gap_ref = (L / 2.0 - delta) % L
```

**这一行正是 `ERRATUM_phaseC_findings.md` §1.2 逐字宣布为 bug 的那一行**
（"off by L/2 = 2.742 m"）。ERRATUM §6 只修了 `_verify_f5_fix.selfplay_to_frozen`
（那处已改为 `(-delta) % L_REF`），**`_ckpt_as_opponent.frozen_layout` 未修，
而新判据脚本恰好 import 了它**。

**(b) 该 bug 在判据的初始状态下立刻显形（实测）**：follower 从 +0.5 m 落后起跑时，

```
真实前向 gap car0→car1            = 0.500 m
BUGGY 适配器 gap 槽 → 归一化 +6.000（撞 clip 上限）→ 隐含 gap = 3.200 m   ← 偏 2.700 m
正确适配器 (-delta)%L → 归一化 +0.600              → 隐含 gap = 0.500 m   ✅
```

**(c) 这使"对手 = 修复后的规则机（31/40 局用内圈）"这句话不成立**（实测）：

```
对手规则机作为 car1(leader)、V2V、+0.5 起跑，follower = ckpt[BUGGY]：
  适配器      回合长  对手 gap 槽范围   隐含 gap 范围      对手 a_lane 取值
  BUGGY       1501 步  [3.38, 6.00]    [1.89, 3.20] m    {0.0}     ← 恒不换道
  CORRECT      339 步  [-0.36, 6.00]   [0.02, 3.20] m    {0.0, 1.0} ← 会换道
```

**决定性**：BUGGY 下对手的隐含 gap **从不低于 1.89 m**，而规则机的切入分支要求
`gap < 0.45`（`overtake_env.py:71`）——**该分支永不触发，a_lane 恒为 0.0**。
修正 gap 后对手的隐含 gap 可达 0.02 m，`a_lane` 出现 1.0，**它确实会切入内圈**。
即：**"31/40 用内圈"这件事，在判据脚本实际使用的适配器下根本不会发生**；
plan §1.3 把"是真对手"与"31/40 用内圈"并列，**两者在判据配置下互斥**。

（§1.3 的 31/40 本身是在**另一配置**下测得的——上一轮评审 T6 记为
"规则 vs 规则、中性起跑"。它与"规则机只作 leader"**不是同一件事**：
后者首发即在前，规则机进入 `delta >= -0.05` 的 "ahead" 分支
（`overtake_env.py:78-81`），**该分支只在 `lane==1` 时才发 `a_lane=-1`（切回外圈），
从不主动切入**。故"用一个不会换道的对手证明它是真对手"，前提不成立。）

**(d) 正例的 1.00 完全依赖这个 bug（实测，适配器对照矩阵）**：

| 被测（follower） | 对手 | win@1.0 | 碰撞率 | 终局 delta |
|---|---|---|---|---|
| ckpt[BUGGY] | rule[BUGGY]（**plan 的组合**） | **1.00** | 0.0% | +2.360 |
| ckpt[BUGGY] | rule[**FIXED**] | **0.00** | 100% | +0.085 |
| ckpt[**FIXED**] | rule[BUGGY] | **0.00** | 100% | −0.105 |
| ckpt[**FIXED**] | rule[**FIXED**] | **0.00** | 100% | −0.105 |
| ckpt[BUGGY] | do-nothing | 1.00 | 0.0% | +2.193 |
| ckpt[**FIXED**] | do-nothing | **0.00** | 0.0% | +0.194 |

**修正任意一侧，正例都归零。** 机制（实测）：BUGGY 下 ckpt 被喂了"前方永远没人"
（gap 槽 9.3% 的步数撞在 clip 上限 6.0），退化成**开环"常驻内圈"**策略
（29.6/30 s 在内圈）——这正是内圈比外圈短 0.94 m（0.83×）白送的领先。

**结论**：§2 表、§3 Caveat 4（"真实超越、非对手失误"）、§4 M1.2 阈值依据，
**全部建立在这个伪影上**。Caveat 4 的说法（"超过去了并保持领先，不是对手崩了"）
恰恰**相反**：越过的是内圈几何，不是对手。

**修订要求**：
1. 把 `_ckpt_as_opponent.frozen_layout` 的 gap 行改为 `(-delta) % L`（或统一改用
   `_verify_rest.frozen_layout_true`），**并把该适配器纳入 `adapter_fidelity_test.py`**
   （现该单测**不 import 任何被测适配器**，只自测了一个局部正确式子——见 §六-4）；
2. 修正后**重跑 §2**，若正例仍为 0.00，则**本判据此刻没有正极**，
   §10.4 的要求未满足，不得登记 M1 阈值；
3. 若要让正极成立，须**在修正后的适配器下重新产生**一个能被承认的正例
   （例如在判据世界内、用判据世界的语义从零训一个 PPO——见 S3）。

### B2. 判据世界**没有随机源**：`RoleWorld.reset(rng, gap)` 从不使用 `rng`

**(a) 源码**：`crit_role_fixed_probe.py:43-58` 的 `reset` 只做
`self.rng = rng`，随后所有位置由 `A_START`、`gap0`、`build_paths()` 决定——
**没有任何一处读 `rng`**。

**(b) 实测（位置与终局差双重确认）**：

```
rng(1)     车的初始位置 = [[0.047561, 0.137915], [0.5, 0.0]]
rng(999999)车的初始位置 = [[0.047561, 0.137915], [0.5, 0.0]]   identical = True

对确定性策略，40 局终局 delta 的 unique 值个数：
  do-nothing       seed0=98000/99000/100000 ：unique = 1 / 1 / 1
  FROZEN CKPT      seed0=98000/99000/100000 ：unique = 1 / 1 / 1
  loiter（见下）    seed0=98000/99000/100000 ：unique = 1 / 1 / 1
  random（唯一有随机性的）                    ：unique = 38–40（噪声来自策略自身 rng）
```

**(c) 后果（这条最要命，直接影响 M1.2 的可执行性）**：
- 训练出的 PPO 在 `deterministic=True` 下评估 ⇒ **胜率只能取 {0.00, 1.00}**。
  §4 的 "≥30 局" 与 "落在 [0.7,0.9] 补 seed" **永远不可能触发**——
  0.8 这个阈值在本判据里**不可达**；
- `crit_power_check.py` 的二项功效计算**数学上正确、但前提不成立**
  （它假设 n 个独立 Bernoulli 样本，实际只有 1 个世界被重复）；
- "3 seed 集" 是 3 次**同一个**结果（实测：三个 seed0 的 unique 均为 1，
  且数值相同）。

**(d) 与 F14 的关系**：F14 说"同一策略驱动两车时结果由初始条件决定"。
本判据消除了初始条件（固定 +0.5），却**没有引入替代的变异源**，
于是结果变成"由策略单点决定"——**从一个退化换到另一个退化**：
判据不再饱和，但**也不再有统计意义**。

**修订要求**：给 `RoleWorld.reset` 加入**真实随机化**，至少：
- `gap0 ~ U(0.30, 0.70)`（而非恒定 0.5）；
- 对手规则机的**参数/初始相位**随机化（或提供一族对手）；
- 可选：`v_max` / `a_max` / `tau` 小扰动（对齐冻结 env 的 `domain_randomize`）。
改完后重测：确定性策略的 40 局应产生**多种终局**（unique ≫ 1）。

### B3. **一个 plan 未列的退化策略通过了判据**（用户点名的检查，结论：不合格）

我实测了 **12 个 plan 未列**的"看似合理但无博弈技能"的策略（完整数据见 §五）。
其中**一个通过，且在高阈值下反超 plan 的正例**：

```python
# 两行，零换道决策、零超越决策：常驻内圈 + 近距刹车
def loiter(o, L):
    return np.array([-1.0 if o[5]*2.5 < 0.4 else 0.0,     # 临近才刹车
                     1.0  if o[4] < 0.5 else 0.0])        # 永远在内圈
```

实测（对手 = 规则机，+0.5 起跑，V2V）：

```
loiter(brk=0.20)  final_delta = +2.5761   passes thr ∈ {1.0,1.5,2.0,2.25,2.5}
loiter(brk=0.25)  final_delta = +2.5524   passes thr ∈ {1.0,1.5,2.0,2.25,2.5}
loiter(brk=0.30)  final_delta = +2.5357   passes thr ∈ {1.0,1.5,2.0,2.25,2.5}
loiter(brk=0.40)  final_delta = +2.4405   passes thr ∈ {1.0,1.5,2.0,2.25}
plan 的正例 ckpt  final_delta = +2.3600   ← 在 thr=2.5 时**掉出**
```

即：**在 plan 宣称可用的区间上沿（2.5），一个两行退化策略通过，
而 plan 自己的正例不通过——判据把两者排反了。**

**机制**：内圈比外圈短 0.83×，常驻内圈即**白送领先**；
刹车只是防止绕圈追上对手时撞车。**全程不涉及"何时切入、何时切回"这一真正的任务决策**——
而后者正是冻结 env 定义的任务（`overtake_env.py` 文件头："learns WHEN to change to the
inner lane to overtake, and when to return"）。

**这直接证伪了 §2 表的隐含主张**（"只有具备超车技能的策略才能通过"）。
按 §10.4，**判据无法区分该退化行为 ⇒ 该判据作废，不得写入验收**。

**修订要求**：判据必须排除"常驻内圈"这一捷径。可选：
- 恢复冻结 env 的**完整成功定义**（不只是终局 delta>thr，还要 `ahead_flag` 后
  **回到外圈**——即把"换道-超越-切回"作为整体成功条件）；或
- 要求**跨过阈值后再回到外圈**才算胜；或
- 加**内圈占用惩罚/限时**，使"常驻内圈"与"按需使用内圈"可分。
无论哪种，都须**先由退化表证明"常驻内圈"落带外**，再投入使用。

再按**正例的实测分布**定阈值（而不是取整数 0.8）——plan 自己的
`crit_threshold_derivation.py` 方向是对的，但它跑在未修正的管线上，结论不可用。

### I4. **判据的因变量在构造上是"饱和斜坡"**——"可用区间 [1.0,2.0]"其实是 wrap 饱和带

这是 B3 的根因，也是本评审发现的**最本质的结构问题**。

`delta` 是**有界量**：`wrapL` 把它限制在 `[−L/2, +L/2) = [−2.7425, +2.7425)`。
而内圈每圈比外圈短 0.94 m（`inner/outer = 0.8282`）。
故**任何**"切到内圈并持续绕圈"的策略，其 delta 会**单调爬到 ~+L/2 然后钉住**
（wrap 阻止它超过 L/2）。实测两条轨迹：

```
loiter（零技能）        delta: t=0 −0.50 → t=15 +2.31 → t=18 +2.44 → 之后在 [2.31,2.44] 锯齿
ckpt[SHIPPED]（plan 正例）delta: t=0 −0.50 → t=15 +2.19 → t=18 +2.37 → 之后在 [2.29,2.37] 锯齿
L/2 = 2.7425   ← 两条都钉在它下方 0.1–0.3 处，永不越过
```

**含义（三条）**：

1. **所谓"阈值的干净 plateau [1.0, 2.0]"不是技能带，是 wrap 饱和带的**横截面。
   在这个带里，`win` 实际测的是"**策略多早切到内圈**"，**不是"有没有超车技能"**：
   loiter 在 t≈0 就切（→2.44），ckpt 切得晚些（→2.36）。thr=1.0 只要求
   "在 30 s 内切到内圈足够早"，**这正是任何内圈绕圈策略都满足的**。
2. **§2 说"thr=2.5 正例也掉（过严）"——诊断错误**。不是"过严"，
   而是**两条策略的饱和点几乎相同**：正例 +2.360、loiter(brk=0.25) +2.552。
   thr=2.5 处**正例掉、loiter 通过**（实测）——plan 只报了"正例掉"，
   **没报 loiter 反而通过**，于是把"倒置"误读成了"过严"。
   （若 loiter 也掉，才谈得上"过严"；实际是在 2.5 处**判据把两者排反了**。）
   故"[1.0,2.0] 可用"这个结论，是把**饱和带的下沿**误读成了"区分良好的区间"。
3. **这解释了为什么"惩罚不作为"的直觉在本判据上失效**：判据的因变量**天然有上界**，
   任何能进入内圈的策略都会顶到天花板附近，于是**天花板附近全是"看起来很好"的策略**，
   而它们彼此只差在"切入时刻"。**本判据在构造上无法把"切得早"与"超得好"分开。**

**修订要求（与 B3 合并）**：判据的因变量必须**不是有界的相对位置**。
至少应取以下之一，**并先用退化表验证常驻内圈落带外**：
- **时间型**：从落后起到 `delta > thr` 的**时间**（越短越好，无上界饱和）；
- **积分型**：`∫ max(0, delta) dt` 的**斜率**，或"领先状态下绕过的圈数"；
- **任务型**：冻结 env 的 `ahead_flag`（一次性的超越事件）+ 切回外圈，
  配合"在 τ 秒内完成"——**这同时堵住常驻内圈**（切回外圈即放弃几何白送）。

### I5. §2 的 mean_delta 列在 BUGGY 下同样不可信

`mean_delta = +2.360`（正例）与 `−0.499`（do-nothing）都出自同一污染管线。
注意 do-nothing 的 −0.499 **恰好等于初始 gap 0.5 的负值**——
说明它根本没动（合理），但也说明这一列**只反映"有没有内圈几何优势"**，
与技能无关。

### I6. §5 步 3 的"复跑退化表"会把错误原样复现

步 3 只要求"复跑确认四项仍过"。若脚本不改，复跑得到的仍是 B1/B2/B3 下的数字，
**门形同虚设**。修订：步 3 须改为"**用修正后的适配器 + 带随机化的世界**复跑，
且必须包含 B3 的常驻内圈反例"。

## 八、结论

**这一稿最值得肯定的地方**：§1.2 的三处修正（C1/C2/C3）我逐条复现**全部成立**，
§3 的四个 caveat（除 Caveat 4 的论证方向）**全部经实测确认**，
§2 的数字**逐位复现**。作者的方向感是准的。

**但它没能交付 §10.4 要的那份表。** 原因是三件事叠加：
正例由一个**已撤回的适配器 bug** 产生（B1）、
判据世界**没有随机源**导致"40 局"是 1 局（B2）、
以及一个**两行的常驻内圈策略**能通过且反超正例（B3）。

**特别回应项目负责人的关注点**："退化表是否包含正例"——
**包含，但那个正例是假的**。这恰好说明"有正例"这件事本身不足以防住
"全是 0 无法分辨"的风险：正例必须**同时**满足"在修正后的管线下仍显著 > 0"。
本判据目前两面都不满足：想证明"区分"，用的却是一个被污染的 1.00；
而修正之后，它自己掉到 0.00，**退化表重新变成"全是 0"**——
用户担心的情况**一层都没躲过**。

**裁决：Reject。** 修订 B1–B3、补齐 I1–I5，重出 plan 后走 review2；
通过后方可登记 M1 阈值、方可开训。
