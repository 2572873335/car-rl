## 一、拦截级问题（导致返工或结论无效）

### B1. §3.1 动作语义切换使 **W5 结论不可迁移**，plan 却只当"实现细节"——最要命的一条

**plan 论断（§1.1）**：冻结 env 用 `v_cmd = v_l + 0.8a`（对手基准），
探针世界用 `v_cmd = v_self + 0.8a`（自身基准），"同一动作含义相反"。

**源码核对（实测，plan 引用行号全部正确）**：
- `overtake_env.py:199-200`：`v_l = self._leader_v(); v_cmd = clip(v_l + 0.8*a_speed, 0, V_MAX)` ✅
- `results/20260920_phaseC_probe/scripts/_selfplay_design_probe.py:101`：
  `v_cmd = clip(self.cars[i].v + 0.8*a_sp, 0, V_MAX)` ✅

所以 F10 的**事实本身成立**。但 plan 有三处不到位：

**(a) "含义相反"措辞不准确**：两者是**基准不同**（对手目标速 vs 自身当前速），
在**对等竞速**相（两车速度相近）时两者几乎重合，差异只在速度分叉时显现。
真正的结构差异不是"符号相反"，而是**冻结 env 里后车自动跟踪前车速度（强稳定先验）、
探针世界里每车速度自指（可漂移/发散）**——这是动力学差异，不是编码差异。

**(b) plan 漏掉了第二个环境差异**：探针世界**同时**缺了冻结 env 的
**曲率限速**（`overtake_env.py:205-207` 的 `R_min` 项，`_selfplay_design_probe.World.step`
里没有）。我一并实测了这两种情形（下表 F-FROZ vs F-V2V），**曲率限速本身显著改变结果**。
F10 把"两个环境不同"简化成"只有速度基准不同"，**低估了不可迁移面**。

**(c) 结论可迁移性——实测（本轮最关键的一条）**：
在**匹配 W5 的 312 更新预算**下重跑**完整联合自博弈**，三种配置各一次：

| 臂 | 速度基准 | 曲率限速 | 1.28M 步末段碰撞率 | 与 W5(自基准,无cap)对比 |
|---|---|---|---|---|
| W5 原跑（`probe_run2`） | 自身 | 无 | **88–100%（钉死）** | 基准 |
| J-V2V | 对手 | 无 | **12–63% 振荡**，末段 ~28% | **不同** |
| J-V2V-cap（=W6 目标 env） | 对手 | **有** | **25–63% 振荡**，末段 ~21% | **不同** |

（命令：`/tmp/_rev_w6_t5j.py`、`/tmp/_rev_w6_t5jc.py`；原始 `probe_run2` 见
`results/20260920_phaseC_probe/probe_run2_joint_selfplay_trend_raw.txt`。）

同时**冻结一方**在 V2V 基准下**仍然成功**（这是好消息）：

| 臂 | 速度基准 | 曲率限速 | 首段→末段碰撞率 |
|---|---|---|---|
| F-V2V | 对手 | 无 | 100% → **0%**（各桶稳定） |
| F-FROZ | 对手 | **有** | 100% → 0%（0↔24% 振荡） |

**结论**：
- **"冻结一方成功"可迁移** ✅（两种基准下都成立）；
- **"完整联合自博弈不收敛（钉死 88–100%）"不可迁移** ❌——在 V2V 基准 + 相同预算下，
  碰撞率**并不钉死**，而是 12–63% 的**大幅振荡**。单种子不为定论，但足以说明：
  **W5 的钉死现象是"自身基准 + 无曲率限速"这个特定环境的产物，plan 不能假定它在
  W6 的新 env 里成立。**
- 更关键的是**方向性**：plan §3.5/W1 想用"混合模式是否重演 W5 的不收敛"做判据。
  但既然"不收敛"的**量级与形态**都随基准改变，这个判据的**对照基线不稳**。

**(d) plan 作者自己已经写了迁移测试，但结果没进 plan**：
`/tmp/_v2v_transfer_test.py`（时间戳 00:28，**晚于 plan 的 00:26**）就是测这个问题的，
其输出为 `collision last=37.0%  => joint verdict under V2V: DIFFERENT from W5!`。
即**作者已识别该风险并动手测，但送审稿未纳入该结果**。送审前应补齐。

**修订要求**：

### B2. §1.2 F11 / §2 R1 / W5"规则机不是对手"——**全部依赖一个算错 L/2 的适配器**

**适配器核对（实测）**：`/tmp/_ckpt_as_opponent.py:46`（`frozen_layout`）写
```python
gap_ref = (L / 2.0 - delta) % L
```
而冻结 env 的定义（`overtake_env.py:125`）是**前向弧长** `gap_ref = (s_other − s_self) % L`。
对peer obs（slot0 = delta_self/2.5），正确式子是 `(-delta) % L`。

**实测（T4b）**，构造"self 落后 other 0.300 m"的状态：
```
真实前向 gap = 0.300 m
plan 的 frozen_layout : gap_ref = (L/2 − delta) % L = 3.042 m  → 归一化 5.68（读作"前方 3 m 没人"）
改正后                : gap_ref = (−delta) % L     = 0.300 m  → 归一化 0.20（正确）
```
**off by L/2 = 2.742 m**——把"紧跟在前车屁股后"读成"前方极远"。

**该 bug 的反转效应（实测 T4c / T7）**：冻结 checkpoint 作 car1、car0 = do-nothing：

| 适配器 | 碰撞 | car1 终局领先 | car1 用内圈 | 领先易手 |
|---|---|---|---|---|
| plan 的（L/2 off） | 22/40 | 18/40 | **0/40** | **0** |
| 改正后 | 22/40 | 18/40 | **22/40** | **22** |

**→ plan §1.2 表格里"用内圈 0/40、领先易手 0 次"这两列是适配器伪影，不是 checkpoint 的属性。**
（"22/40 碰撞"与"终局领先 = 地板"**仍成立**，即"该 checkpoint 不是好对手"的**结论**
大体幸存，但**所列证据有两列是假的**。）

**更严重——同样的 bug 污染了 W5 的"规则机不是博弈对手"结论，而 §2 R1 正建立其上**：
`_verify_f5_fix.py:49-53`（**已归档**，与 /tmp 版逐字节相同）的 `selfplay_to_frozen`
**把 gap 硬编码成 1.0 m**：
```python
return np.array([(1.0 - 0.2) / 0.5, delta_n, v_self, e_lat_n, lane, v_other], np.float32)
```
规则机 `baseline_action_ot` 的**切入分支要求 `gap < 0.45`、刹车分支要求 `gap < 0.15`**
（`overtake_env.py:64-74`）。**gap 被钉在 1.0 ⇒ 两个分支永不触发 ⇒ 规则机永不换道。**

**实测 T6（规则 vs 规则，中性起跑，40 局）**：
```
gap 硬编码 1.0（= W5/plan 用的） : ever-inner 0/40   领先易手 mean=0.00  零易手 40/40
TRUE gap（改正后）              : ever-inner 31/40  领先易手 mean=0.45  零易手 22/40
```
**→ "规则机 40/40 局零次领先易手、零次用内圈"是适配器把 gap 伪造掉造成的，
不是规则机的性质。** 规则机在**正确观测**下**会**使用内圈、**会**发生领先易手。

**后果（三处连锁）**：
1. §2 **R1**（把验收从"规则基线"改为"专门训练的快照"，依据 = 规则机不是对手）**地基被抽掉**；
2. `findings_phaseC_selftest.md` F5 后续的"P2 判据不可修复"与 `ASSUMPTIONS.md` 中
   "冻结规则机不是博弈对手"的登记**均须重新评估**；
3. plan §1.2 的"诚实披露"**只把 ARM B 一行标为无效**，但**ARM B 的失效机理
   （伪造 gap）与规则-vs-规则测试是同一个**——揭示不彻底，同一污染的其他行未作排查。

**修订要求**：以**正确的 gap 适配器**重跑 §1.2 三臂 + 规则 vs 规则，
重出 §1.2 表与 §2 R1 的依据；并在 plan 里显式声明"旧结论作废/待复核"。

### B5. §3.4 单方失败计分：**物理上不可实现 + 与 R2 自相矛盾**

**(1) 不可实现**：plan 要"一车碰撞即该车判负"。但**两个世界的碰撞判定都是
`2D 距离 < 0.12 m`**（`_selfplay_design_probe.py:113`、`overtake_env.py:234`），
**不记录相对速度、不记录航向、不记录谁侵入**。实测 T3（326 次随机对撞）：
```
同车道大体重合航向（追尾样） : 137
跨车道或大夹角（侧擦样）     :  81
含混                        : 108
|delta| at collision: mean=0.120 m  median=0.111 m
航向差 dh: mean=0.34 rad, frac(dh>0.5)=0.22
```
**33% 的碰撞是含混的、25% 是侧擦**——物理里**没有"谁撞了谁"这个量**。
"该车判负"无法计算。

**(2) 与 R2 矛盾**：R2 明确"终止罚（碰撞/出界）**同时施加两车故不零和**"。
若碰撞对**双方**都 −500，则"撞车方判负、另一方判胜"的 +1/−1 **叠加在共享 −500 之上**：
撞车方 = −501，另一方 = −499。此时**主动撞车被 −500 严格支配**（自杀式拦阻**不**划算）。
反过来，若按 §3.4 的自然读法让"胜方**免罚**"，则**封堵/brake-check 立刻变划算**。
**plan 对这两种读法未作区分**，而二者训练出的策略截然不同。

**(3) 出界可归因，碰撞不可**：`e_lat` 是**每车自身**的量，故"该车出界"可判；
但 collision 不可。plan 却把二者并列成同一条规则。**须拆开写。**

**修订要求**：(a) 明写碰撞罚是**共享**（承接 R2），还是**引入归因**；
(b) 若引入归因，须先给出可实现的肇事判据（相对接近速度 / 侵入角），
**否则不得声称"该车判负"**；(c) 出界单独成条（可归因）。

### I3. W1 判据**欠定义 + 对窗口口径不稳健**（实测回放）
plan W1："对抗模式碰撞率**不高于**首 20%（相对 ≤ 1.2×）"。

更本质：W1 用**桶均值的相对比**测"稳定"，而 W5/F9 的不稳定形态恰是
**大幅振荡**（我的 V2V 臂就是 12–63% 摆动）；一个振荡但桶均值不升的训练会被 W1 判"稳定"。
**修订**：把"稳定"操作化为**方差/极差**判据（如末尾窗口碰撞率 std ≤ 阈值），
并定死窗口口径；同时**补一条绝对失败率上限**（见 B4/S2）。

### I4. W4 的 ≥8/10（10 seed）**分辨率不足**（实测 N3）
二项分布：真值 p=0.7 时 P(≥8/10)=0.38——**8/10 这条线在真实退化时也只有 38% 概率触发**；
p=0.9 时 P(≥8/10)=0.93。即 **8/10 几乎无法区分"轻微退化"与"无退化"**。
本项目的**自身规范**是边界结论补到 30 seed（见 `ASSUMPTIONS.md` H6：
10 seed 恰在阈值 → 补跑 30 seed）。plan 反而**从 10/10 放宽到 8/10**，方向相反。
**修订**：任务模式评估用 ≥30 seed，或至少声明"8/10 仅作粗筛，边界须补 seed"。

### I5. **灾难性遗忘**这条风险，plan 的 70/30 无法验证也无比值出处
- 70/30 **照抄 roadmap 原文**（`roadmap.md` W6 行的"70% 任务 + 30% 对抗"），
  plan 未给任何依据或理由，属"抄路线图"（评审问答干条 #3 已指出）。
- 更实际：W4 只有 10 个 seed（I4），**分辨率根本测不出遗忘**；plan 自己也把
  "灾难性遗忘"列为"中高"概率风险，却只给 W4 这一道 8/10 的弱门。
- **修订**：给出 70/30 的敏感性设计（至少两档比例，如 80/20 与 50/50），
  或明写"比例为待调超参，本轮固定 70/30 并记录依据"；W4 提升到 30 seed。

### I6. **缺一条绝对验收**：W6 通过时**碰撞率可以仍然很高**
W1–W4 全过，也不排除"对抗模式碰撞率 = 24%"（W5 冻结一方的实测末值就是 24%）。
对**物理双车演示**而言，24% 碰撞率是不可用策略，但 plan 没有一条判据卡这个绝对值。
**roadmap 的原始验收是"行为合理"，plan 用"胜率 ∈ 带"+"可降"替换之，丢掉了绝对量。**
**修订**：补一条"对抗模式碰撞率 ≤ X%（给出 X 的依据），≥N 局 ≥3 seed"。

## 四、对 §待评审确认点 7 问的逐条答复

**Q1（§2 R1：验收由"规则基线"改为"专门训练的快照"）**：
**方向可接受，但当前依据已被推翻（B2）**。R1 的理由是"规则机不是对手"，
而该结论来自 gap 被伪造的适配器（实测：改正后规则机 31/40 局用内圈）。
**须以正确适配器重测后再定 R1**。另：R1 把验收换成"快照"后，
必须补**绝对**判据（I6），否则"快照也能跑"不构成验收。

**Q2（§3.1 统一到 V2V 基准是否正确 / 是否需披露历史差异）**：
**选择本身合理，但处置方式错误**。统一到 V2V 提升与冻结 env 的可比性，
**确实牺牲与 W5 的可比性**（B1 实测：W5 的"钉死"在 V2V 下不复现）。
**必须在 plan 里显式披露**"W5 结论建立在自身基准 + 无曲率限速之上，
其'不收敛'形态不迁移到 W6 env"，并**随之调整 W1 的对照基线**。
`_v2v_transfer_test.py` 的已有结果（"DIFFERENT from W5"）应一并登记。

**Q3（§3.2 8 维是否足以表达"对手意图"；有无更强自视角代理）**：
**不足，且不是本轮该做的事**。`lane_other` 与 `|Δlane|` 只在对手变道瞬间有信息，
其余时刻是常量；真正的意图代理更像**对手的横向速度 / 相对接近率**（仍自视角可观测）。
但更优先的是：**新增维度使锚点门 A 与 checkpoint 复用失效（B3）**。
建议按 S1/S2 推迟。

**Q4（§3.4 是否引入"故意撞车"退化策略）**：
**两条问题，且比 plan 设想的更根本**：
(a) **物理无法归因肇事者**（实测 T3：33% 含混、25% 侧擦），"该车判负"**不可计算**；
(b) **是否被钻空子取决于一个 plan 没定的选择**——碰撞罚若**共享**（R2 的读法），
则 −500 严格支配自杀式拦阻（**不**划算）；若让"胜方免罚"（§3.4 的自然读法），
则**封堵/brake-check 划算**（**被钻空子**）。plan 对二者未作区分。
**不对称内圈不改变这一点**：碰撞是 2D 邻近事件，与两车车道长短无关。

**Q5（§4 W2 [35%,65%] 是否合理；会否因对手池过弱而失去区分度）**：
**不合理，且比"对手池过弱"更糟**——**退化策略就在带内**（实测：do-nothing 0.58、
random 0.53）。这不是"对手太弱"，是**判据本身无信息**（W5 F5 已证）。

**Q6（§4 W4 ≥8/10 容忍度是否有依据）**：
**无依据、且分辨率不足**（实测 N3）。10 seed 下 8/10 在 p=0.7 时只有 38% 触发概率。
按项目自身 H6 规范，边界结论应补至 30 seed。

**Q7（§5.1 门 A 若 checkpoint 无法复现 10/10，判 env 不等价还是 ckpt 过拟合？如何区分）**：
**给一个可执行的 2×2 判别方案**（plan 未给方法，这是本问的核心缺失）：

1. **先消除可行性障碍（B3）**：建 6 维 shim env（只暴露前 6 槽）喂 checkpoint。
2. **加一个阳性对照**：在**新 env 的任务模式**下**从零训一个 PPO**（分钟级），
   得"新 env 的原生策略"。**注意此策略用 8 维还是 6 维要固定**，比较需同维。
3. **四格判别**（每格 ≥10 seed，固定 seed 集）：

   | 被测策略 | 新 env 任务模式 | 原冻结 env | 判读 |
   |---|---|---|---|
   | 冻结 ckpt（6 维 shim） | 10/10 | 10/10 | **等价** ✅ |
   | 新训策略（同维） | 10/10 | 10/10 | 等价（交叉确认） |
   | 冻结 ckpt 低 / 新训策略高 | 3/10 | 10/10 | **checkpoint 过拟合旧 env**（或 shim 投影有损） |
   | **两者都低** | 2/10 | 10/10 | **新 env 与冻结 env 不等价**（env 侧 bug） |

   判读逻辑：**新训策略是新 env 的"能力上限探针"**——它若也上不了 10/10，
   问题在 env（不等价）；它若轻松 10/10 而冻结 ckpt 不行，问题在 ckpt（过拟合）。
   这是把一个二分难题转成"用阳性对照把 env 因子与 policy 因子解耦"。
4. **补充交叉项**：把新训策略放回**原冻结 env** 评估。若新训策略在原 env 也 10/10
   而冻结 ckpt 在新 env 只有 3/10，则**过拟合诊断成立**；若新训策略在原 env 掉分，
   说明两 env 的**任务相**本就不一致，属 env 不等价。

## 五、我自己发现的、plan 未提及的问题

1. **plan 漏掉第二个 env 差异（曲率限速），且它可改变结论**（实测：F-V2V 末段 0% vs
   F-FROZ 末段 0% 但全程 0↔24% 振荡）。F10 只讲了速度基准，差异清单不完整（B1b）。

2. **§1.2 的"诚实披露"揭示得不彻底**（B2）：plan 只标 ARM B 一行无效，
   但 ARM B 的失效机理（伪造 gap）**与规则-vs-规则测试同源**，
   而后者恰恰是 §2 R1 与 W5 F5 的支柱。披露应扩到"所有用 `selfplay_to_frozen` 的结论"。

3. **"地板"参照的构造偏差**：plan 用 do-nothing 的"终局领先 18/40"当地板，
   但中性起跑下**两相同策略**本身就接近 50/50（实测 0.52/0.58）。
   "18/40 = 地板"其实是"中性起跑的对称基线"，**不是"弱策略基线"**——
   拿它证明"checkpoint 与 do-nothing 等价"逻辑上偏弱（任何中性起跑策略都 ≈18/40）。
   真正的地板应是**结构性落后**（后车固定起跑）下的数，或改用 `E[|delta|]`。

4. **门 B"验证环境自洽（不瞬间碰撞、终止分布合理）"无阈值**：
   实测同一对局，plan 适配器下 0/40 碰撞、改正适配器下 34/40 碰撞——
   "自洽"完全由适配器决定。**该门不可证伪**，须给数值阈值。

5. **§4 的 W1 丢了 W5 P1 的 `value_loss` 子句**（W5 P1 有"value_loss 非 NaN 且末段
   不单调增长"），W1 只剩 `train/std`——发散信号被移除。W5 run2 的 max value_loss
   达 1.28e5，是真实发散征兆，不应失检。

6. **W3"涌现行为"完全主观**（"出现 ≥1 类非平凡行为，须视频/轨迹佐证"），
   而它是 RQ3 的**核心交付**。在 17.2% 内圈不对称 + 30 s ≈ 3.8 圈的设定下，
   "封堵/关门"极易与"普通跟车/换道"混淆。**须给可操作的判据**
   （例："对手进入内圈的 ≥X 次中，自车在其后 Y 米内跟进内圈的次数显著高于随机基线"），
   否则"涌现"可由叙事自由裁量（正是 W5 评审批判"总能说点什么"的同类风险）。

7. **"冻结一方的成本"被低估**：plan §1.3 称"生产联赛成员是分钟级"，依据是 W5
   一次 409,600 步 / 832 s。但 (a) 那只是**一个**对手；(b) 池上限 5 ⇒ 至少 5 次训练
   + 评估；(c) 我本轮实测同样的 409,600 步在**并发**下耗时 **1008–1282 s**。
   "分钟级"在池规模上至少是"十几分钟 × 5 + 评估"，措辞须改实。

8. **plan 未声明新 env 的哈希/冻结计划**：`selfplay_env.py` / `train_selfplay.py`
   将承载 W6 的**结论级**环境（铁律 2/4 语境），但 §6/§8 只说"创建后补 §8 哈希"，
   **未写"训练前定版并算 sha256"**。W5 探针可豁免铁律 4，**W6 是产出结论的训练，
   不豁免**（plan §5.2 已自认），则环境冻结与哈希存证应**前置**到训练前。
