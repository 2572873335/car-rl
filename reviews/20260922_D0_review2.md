## 一、拦截级问题（每条带实测命令与输出）

### B1（★ 最重要）D0.2「RL ≤ 8」的**聚合单位未定义**——补 seed 反而证明这是**结构性贴线**，不是抽样噪声

plan §2.2 D0.2 写「RL ≤ **8** 且零碰撞」，§2.2 边界警报说「补 30→100 seed 后复判，若越过 8.00 则判未通过」。
**但「RL ≤ 8」是对 100 个 seed 的哪个量**？是**每 seed settled 均值**，还是**每回合**，还是**100 seed 的总均值**？plan 从未定义。

实测（本评审，settled obs-cm = 200×|e[20%:]| 均值，grid `d=0.50 v=1.00 constant`，checkpoint `4231a613…`）：

```
100 seed 聚合（4 个独立 seed 块，每块 100 seed）：
  seeds 2000-2099: agg_mean=7.973  std=0.160  min=7.582 max=8.386  ep>8.00: 39/100
  seeds 3000-3099: agg_mean=7.946  std=0.160  min=7.449 max=8.337  ep>8.00: 36/100
  seeds 4000-4099: agg_mean=7.954  std=0.160  min=7.502 max=8.544  ep>8.00: 37/100
  seeds 5000-5099: agg_mean=7.979  std=0.160  min=7.483 max=8.463  ep>8.00: 44/100
P+FF 同格 n=100: agg_mean=5.731  std=0.120  零碰撞
```

**结论（实测）**：

1. **按「100 seed 的聚合均值」判 → D0.2 通过**：4 块独立测量均为 **7.946–7.979 < 8.00**，
   均值的标准误 ≈ 0.016（=0.16/√100），8.00 距均值约 **1.7σ** ⇒ 通过但仅 ~95% 置信。
2. **按「每 seed / 每回合」判 → D0.2 未通过**：**36–44% 的 seed 单回合就 > 8.00**（最大 8.544）。
3. **关键：把 30→100 seed 并不能「判定」这个边界**——30 seed 的 7.98 与 100 seed 的 7.97 **一致**，
   说明该值**稳定地坐在 8.00 下方 0.03cm**，是**结构性贴线**而非抽样抖动。plan 的处置
   「补 seed 后越线即判未通过」在**未定义聚合单位**时**不可执行**。

**⇒ 这正是 review1 R3「一个验收门靠读者猜单位定生死 = 不可判」的同型复发**（这次换成了聚合维度）。
**必修**：在 §2.2 明写聚合定义，建议定为
「**聚合 = 100 seed 的 per-seed settled mean 的均值**；判据作用于该聚合值，并同时报告其 ±SE」；
并明说「单回合越线不作为判负依据」（否则 D0.2 按构造必挂）。若采用此定义，D0.2 **通过（7.97±0.02）**，
但 doc 必须写明「余量 ~0.03cm，处于铁律『边界』语义」——不要假装它有余量。

> 附：D0.2 的阈值 8 是**从它要判的量本身（7.98）反推**的，违反 review1 R3 要求的「留有余量」。
> 且该格 **P+FF 亦满足 D0.2（5.74 ≤ 8）** ⇒ D0.2 是绝对门、不区分 RL/P+FF，这是设计（相对比较交 D0.4），
> 但须在 doc 显式声明，避免被读成「D0.2 证明 RL 在 AGV 速度够用」。

### B3 wrapper 的 `D_DES` **在异常路径下泄漏**，plan 实现无 try/finally——会静默污染后续所有格子

plan §1.1 的 wrapper：`reset()` 设 `follow_env.D_DES = d`，`close()` 还原 0.20。
实测（本评审 leak 探针，见 §五脚本）：

```
(c) 'D_DES' in baseline_action body: False        ← baseline_action 不读 D_DES（伪风险，证伪）
(a) RL wrapper reset d=1.00 → fe.D_DES=1.0 ; close() → 0.2
    P+FF wrapper reset d=0.30 → fe.D_DES=0.3 ; close() → 0.2     ← 正常交叠：干净
(b) 异常抛出、close() 未执行 → fe.D_DES 仍为 0.50
    raw env（未用 wrapper）此时 chased D_DES=0.50: terminal gap=0.463（不是 0.20）  ← 泄漏确凿
frozen follow_env.py untouched: True (941c447b969c2fa1)
```

- **好消息**：`baseline_action` 只对 obs 反归一化、**不读 `D_DES`**（`(c)` False），
  故 P+FF 在**策略层**免疫该泄漏；正常交叠（RL→close→P+FF）也干净。
- **坏消息**：**任一回合在 `reset()` 与 `close()` 之间抛异常，`fe.D_DES` 即滞留**，
  随后**任何**新建的裸 env（含下一个格子）都会**追错的设定点**（实测追 0.50 而非 0.20）。
  plan 将跑 9 格 × 3 策略 × 最多 100 seed —— **一次崩溃就静默污染其后的全部格子**，而表仍会打出数字。
- `_verify_r4_grid.py` 同型：`fe.D_DES` 在 `run()` 入口设、**只在 `main()` 最末（line 98）还原**，
  中途崩溃同样泄漏。

**⇒ 必修**：wrapper 用 `try/finally`（或 context manager）保证还原；并在**每次 run() 后断言
`fe.D_DES == 0.20`**（廉价守卫，防静默污染）。这与 §5b「落盘脚本须可复现」是同一条纪律的延伸。

## 二、重要问题 / 建议（非拦截）

### I1 0.55 的锚定：plan 的「+10% 裕度」不是最强论据——训练分布**本就含 0.70 m/s 瞬时领车速度**

confirm point 2（0.55 来源）可给一个**比「训练上限 0.50 + 10%」更硬**的依据：
`follow_env._leader_v()`（line 90–98）对 `sinusoid` 行为做 `v = v_set·(1+amp·sin(...))`，
`amp ~ U(0.2, 0.4)`（line 117）。**训练期 v_set 最大 0.50、amp 最大 0.4 ⇒ 训练中领车瞬时速度达
0.50×1.4 = 0.70 m/s**。故 `v=0.55`（constant）**落在训练已见领车速度带之内**，判「分布内」有实证依据，
不是拍脑袋的 +10%。**建议 §2.3 引这一条替换纯裕度论证**（并注明 `_leader_v` 有 `clip(...,0.05,1.0)` 上限，
故 0.70 < 1.0 成立）。
