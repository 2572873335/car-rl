## 一、拦截级问题（导致返工或结论无效）

### B1. §4 的核心方法论条款自相矛盾，且实测为假——最要命的一条

§4 声称："**对称零和 ⇒ 同策略互搏期望回报恒为 0，回报不会上升**"，并把它列为
"本轮最重要的方法论条款"。但这条**与 §3.2 自己的话直接冲突**：
§3.2 结尾写"**内圈更短更快，故本博弈本质上不对称**"。一个**不对称**博弈里，
共享策略的自对弈期望回报**不恒为 0**。

**实测（用冻结几何 + plan §3.3 的字面奖励 `r_self=+w(δ_self), r_other=−w(δ_self)`，
冻结初始条件 = car0 在 A_START、car1 落后 gap0∈[0.3,1.0]）**：

```
v0=0.5 v1=0.5:  E[R0]= +317.15  E[R1]= -317.15   sum=0  mean_of_agents=0
v0=0.4 v1=0.6:  E[R0]=  +18.51  E[R1]=  -18.51   sum=0  mean_of_agents=0
v0=0.6 v1=0.4:  E[R0]=  +74.12  E[R1]=  -74.12   sum=0  mean_of_agents=0
```

**两条事实**：
1. `R0+R1≡0` 是**字面取负的同义反复**，不构成"无信息"的论据；
2. **每个 agent 的回报 E[R_i] ≠ 0**（实测 ±317），因为初始位置固定、两角色
   （被追/追）**结构上不同**。

**后果**：plan 让执行者**主动丢弃最直接的进度信号**（per-role / per-agent 回报、
角色条件回报）。在 plan 自己选定的"非对称 + 固定初始条件"设计下，per-agent
回报恰恰是**有效**信号。**修订**：把措辞改为——
> "**对称**零和自博弈（两 agent 同初始分布、角色可交换）下，**策略对自身**的
> 期望回报恒为 0；**本设计不对称（内圈更短 + 固定初始位形），故 per-agent /
> per-role 回报是有效信号，必须记录。"
并把 `E[R_self]`、`E[R_other]` 加入 §4 的"有效进度信号"清单。

### B2. §4 P1 的熵判据**会在健康训练上误判失败**，从而错误地枪毙 RQ3

P1 定死："末 10 次更新的平均策略熵 ≤ 首 10 次的 **0.8×**"。

**实测（`ent_coef=0.01`、n_steps=256、8 并行、SB3 2.9.0、`device='cpu'`，
plan §6.3 的全部超参，跑 120 次更新）**：

```
seed=0: entropy 首10=2.8575  末=2.9320  ratio=1.026   std_last=1.0501
seed=1: entropy 首10=2.8250  末=2.9335  ratio=1.038   std_last=1.0560
（中途 ratio 全程落在 1.00–1.04，从未低于 0.99）
```

**根因**：`ent_coef=0.01` 的熵奖励**主动把熵往上顶**；且 2 维高斯的最大熵
`= 0.5·ln(2πe)·2 ≈ 2.84`，实测 2.83–2.93——策略**基本贴在最大熵**，熵不下降。
这条阈值**与优化目标方向相反**，正常训练就会判失败。
（说明：本轨迹用的是**冻结 `OvertakeEnv` 的单智能体奖励**，非零和自博弈奖励；
但它足以证明"`ent_coef=0.01` 下熵不塌"这一机制，且 plan 对 0.8× **未给出任何依据**。）

**附加可执行性陷阱**：SB3 2.9.0 的日志字段是 **`train/entropy_loss`（负值）**，
策略熵 = `−train/entropy_loss`（`ppo/ppo.py:287`，`entropy_loss = -th.mean(entropy)`，
`ppo/ppo.py:250-254`）。执行者若直接对 `train/entropy_loss` 套"≤0.8×"会**符号反了**。
**修订**：P1 改成**可执行的塌缩判据**——例如"`train/std`（SB3 直接记录，
实测可用）在末 10 次更新**不单调趋 0**"或"`train/approx_kl` 不持续为 0"，
并显式写明"熵 = −`train/entropy_loss`"。**不要用未加论证的 0.8× 熵比。**

### B3. §3.2 的"观测严格互为镜像"在跨车道时**不成立**，且与 §3.2 末句自相矛盾

§3.2 写"两视角**严格互为镜像** ✅"，镜像规则 = "d 取反、v_self↔v_other、
**e_lat 与 lane 不变**（后两者本就自指）"。

**证明其不成立**（不需要实验）：镜像算子 M 把 `O_other` 映到 `O_self`。当两车
**处于不同车道**时（=本博弈的全部战略内容），`O_self` 的 slot4 = `lane_self`，
`O_other` 的 slot4 = `lane_other`，且 `lane_self ≠ lane_other`。M "不变"slot4，
故 `M(O_other).slot4 = lane_other ≠ lane_self = O_self.slot4`。**镜像失败**。
`e_lat` 同理（各自相对**自己车道**的横向偏差，跨车道时不可比）。

plan 在同一节里同时写下"**严格镜像 ✅**"与"**本质不对称**"——**这两句不能同时为真**。

**但请注意问题的真实性质**（这决定了修订方向）：共享参数自博弈**真正需要**的
不是"两视角互为镜像"，而是"**两行用同一个编码函数、以各自为 self**"。plan 用
**有符号** `d` 让编码成为同一个函数——这一步**是对的、有价值的**。"互为镜像"
是一个**既非必要、又非成立**的额外断言。**修订**：删去"严格镜像"的措辞，改为
"两行采用同一 self-view 编码函数（有符号 d 保证编码与角色无关）"，并**删去
§4 中一切依赖"对称性"的推论**（见 B1）。

**附带（同样真实，但此节独有）**：§3.2 说用 `wrap` 到 `(−L/2, L/2]` 后
`d_other = −d_self` **严格成立**。**边界情形实测为假**：

```
s_self=0, s_other=L/2 :  d_self=+2.7424668  d_other=+2.7424668  sum=+L  → 镜像失败
20 万随机对: 0 次违例（测度为 0）
```

而**冻结 `overtake_env.py:126-127` 用的是 `(s_f − s_l + L/2) % L − L/2`，即
`[−L/2, L/2)`**——与 plan 标的 `(−L/2, L/2]` **是相反的开闭区间**。同一状态
（恰好对径）两者给出**反号**的 delta。**修订**：与冻结 env 统一为
`[−L/2, L/2)`，并注明"对径点两侧符号约定与冻结 env 逐字一致"。

## 二、重要问题（影响质量但不致命）

### I1. §3.1 的"同一观测编码语义"与 §3.2 的实际布局**不符**

§3.2 给出的 6 维是：
`[d_self/2.5, v_self/1.3, v_other/1.3, e_lat_self/0.25, lane_self, (L/2−|d_self|)/2.5]`。
冻结 `overtake_env.py` 的 6 维是：
`[(gap_ref−0.2)/0.5, delta/2.5, v_f/1.3, e_lat/0.25, lane, v_l/0.5]`。
**逐槽比对**：slot3（e_lat）、slot4（lane）一致；**slot0、slot1、slot2、slot5
全部是不同物理量或不同归一化**（如冻结 slot0 是**前向** gap∈[0,L)，plan slot0 是
**有符号**位移∈[−L/2,L/2)，且归一化 ÷0.5 vs ÷2.5）。§3.1 却称"**同一观测编码
语义**、W6–W9 结果可与冻结基线**直接可比**"。**只动一个变量**（领头车改策略）
的可比性主张因此**不成立**。**修订**：要么保留冻结 6 维布局并用第 6 槽承载
镜像所需的量、要么明写"观测布局已变（给出对照表）"，并相应下调"直接可比"的措辞。

### I2. §4/P2 的"规则状态机对手" **没有接口**——冻结 `baseline_action_ot` 接不上新 obs

P2 要"对**规则状态机**对手胜率 ≥50%"。项目里唯一的规则对手是
`overtake_env.baseline_action_ot(obs)`，它**按冻结布局解码**：
`gap=obs[0]*0.5+0.2, delta=obs[1]*2.5, lane=round(obs[4])`
（`overtake_env.py:59-61`）。**实测**：把 plan 布局的 obs 喂给它，
slot0 被读成 `gap=obs[0]*0.5+0.2`（其实是 d/2.5）、slot1 被读成 `delta=obs[1]*2.5`
（其实是 v_self/1.3）——**全是垃圾**。plan 未提如何适配。**修订**：明确
"规则对手需按新布局写适配器（或保持冻结布局使 `baseline_action_ot` 可直接复用）"。

### I3. 胜负判据 `delta_self > 0` 在**套圈**时失效

冻结外圈 `L=5.4849 m`（实测），内圈 `L=4.5424 m`（比值 **0.828**）。30 s 内一辆
0.7 m/s 的车跑 **~21 m ≈ 3.8 外圈**。plan §4 的"胜 = 固定 30 s 视界结束时
`delta_self>0`"在**套圈**后失效：`delta` 在 ±L/2 处回绕，"谁在前"不再由 `delta`
的符号定义。冻结 env 靠 `ahead_flag`（**永不重置**，`overtake_env.py:229-231` 的
注释专门讨论了这个坑）处理套圈——plan 的判据**没有**等价机制。**修订**：胜负
必须引入**累积圈数 / ahead_flag 式**的量，或缩短视界到 ≤ 一圈（并核算 30 s
是否仍在规划内）。

### I4. §3.4 "同生共死"两个后果 plan 未处理

1. **无辜车被连坐**：一车出事、另一车没事，却同时置位 `dones`。plan 未定义
   碰撞/出界罚分如何分摊；零和奖励 `r_self=−w(δ)` 是**逐步**的、对称的，
   若对两行都施加"死亡罚"则**错误惩罚未肇事车**。
2. **抹掉"封堵/逃脱"信号**：封堵的 PAYOFF 恰恰是"**让对手失败**"。强制同时
   终止 + 只在 T=30 比 delta，**排除了"致对手出局"这一制胜路径**——而这正是
   §3.2 声称"内圈不对称使封堵有意义"的来源。**修订**：给出"单方失败即分出
   胜负"的终止与计分规则，或**显式论证**探针阶段为何放弃它（并把它列入 W6
   待办，而非默认）。

> 补充：`同生共死` 的**真实动机是 SB3 约束**——`DummyVecEnv.step_wait`
> （`dummy_vec_env.py`）对**每一行独立 auto-reset**，若两行共享一个 world 而
> done 不同步，行间相位会错。这是真问题，但 plan 应**写清它是 SB3 的 workaround**，
> 而不是把它当成博弈设计的自然选择。

### I5. §5 对铁律 4 的**适用范围理解错误**（但结论无害）

- **算术对**：1,280,000/(16×256)=**312.5** ✅；100,000/4096=24.4 ✅。
- **但探针门本就豁免铁律 4**。铁律 4 的原文语境是"**产出结论的训练**"，
  而项目**自己**在 `Makefile:4-6` 写死：
  > "the short runs **intentionally violate** the project's '>= 300 gradient
  > updates' rule. It is a **functional smoke test, NOT a result reproduction**."
  plan §5 **已经**用这条逻辑给 5k smoke 开了豁免，却拒绝把同一逻辑用到
  "定义上就是机制 smoke"的探针上。**论证自相矛盾**。
- **1.28M 是好建议，但要换理由**：实测 16 行 stub VecEnv 吞吐 ~7,800 rows/s
  （纯 python，无物理）；plan §1.2 实测真实物理 2,417 steps/s 单环境。
  1.28M 在此量级**仍是分钟级成本**，且更长的轨迹让 P1/P2 更有信号。
  **修订**：把 §5 改写为——"铁律 4 对探针**形式上豁免**（`Makefile` 先例）；
  本项目**主动选择** 1.28M，因为它便宜且使进度信号更清晰——**而非因为铁律 4 要求**"。

### I6. §4 P3 近乎空洞，且阈值无依据

"固定观测批上速度维动作标准差 > 0.05"：(a) **阈值太低**——实测 `train/std≈1.0`，
任何未完全塌缩的策略都远超 0.05，**测不出塌缩**；(b) **"固定观测批"未定义**；
(c) 把 aleatoric（策略 σ）与 epistemic（状态相关均值变化）**混为一谈**。
**修订**：直接用 SB3 记的 `train/std`（实测可用），阈值按"塌缩"设（如
末 10 次 `train/std < 0.05` 判塌缩），并写明评估批的构造。

## 四、对 §待评审确认点 6 个问题的逐条答复

**Q1（§2，IPPO 代 MAPPO 可否）**：**可接受**。理由：`AGENT_HANDOFF.md §4`
已**预先背书**"独立 PPO + 参数共享的最简实现"，且探针的问题是"**机制**能不能
跑通"，不是"MAPPO 本身好不好"。共享参数 PPO 是合法的最小实例化，MAPPO 的
集中式 critic 是正交增益，W6 再叠加不迟。**但**：§1.3 的证据**只覆盖探针机制**，
不要拿它论证"W6 也不需要 RLlib"（见 S2）。

**Q2（§5，100k→1.28M）**：**算术正确，但前提错**。铁律 4 **不约束探针**
（`Makefile` 先例）。1.28M **仍是好建议**（便宜、信号更足），但**理由要换**：
不是"为了不破铁律"，而是"反正便宜、多跑更好"。见 I5。

**Q3（§3.2，镜像方案是否对/有无退化情形）**：**方案的核心（有符号 d）对；
"严格镜像"的断言错**。三处问题：(a) 跨车道时 `lane`/`e_lat` **不可镜像**
（证明见 B3）；(b) 对径点 `d_other=−d_self` **边界失效**、且开闭区间与冻结 env
**相反**；(c) `(L/2−|d_self|)` 是 d 的函数，plan 的镜像规则清单**漏了它**
（它是镜像不变量，需显式声明）。**未提的退化情形**：跨车道本身就是退化情形；
另有**套圈**（见 I3）与**两车同在一条路径但 s 坐标不同源**的风险（见 §五-#2）。

**Q4（§4，阈值过严/过松；"回报恒 0"是否认同）**：**"回报恒 0"不认同**
（B1，实测 per-agent 回报 ±317）；**P1 过严且方向错**（B2，健康训练 ratio≈1.0，
0.8× 会误杀）；**P2 分母未定义 + 随机基线语义退化**（见 §五-#4）；
**P3 过松**（I6）。三条阈值均需重设。

**Q5（§3.1，差异清单是否完整）**：**不完整**，且**与 §3.2 矛盾**（I1）。
至少缺：观测布局差异、规则对手适配（I2）、套圈胜负判据（I3）、
终止计分（I4）、镜像在跨车道的失效（B3）。

**Q6（更廉价的证伪）**：plan 问了但**没答**。我的具体方案见 §五-6。

## 五、我自己发现的、plan 未提及的问题

1. **§3.2 第六槽 `(L/2−|d_self|)/2.5` 的镜像归属未声明**：它是 `|d|` 的函数，
   镜像下**不变**——需显式写明，否则执行者按"d 取反"套用会得到 `(L/2−|d|)`
   与 `(L/2−|−d|)` 看似不一致（数值其实相同，但**推理链断裂**）。

2. **`d` 必须在"共同参考路径"上测，plan 未声明**。冻结 env 的 `_measure`
   （`overtake_env.py:132-141`）把**两车 s 都投影到外圈**（"common reference"），
   正因如此 `delta` 才可比。若 plan 让每辆车在**自己车道**上算 s，则两车 s 属于
   **不同总长**（5.48 vs 4.54）、不同坐标系 → `wrap(s_other−s_self)` **无意义**，
   而 `d_other=−d_self` 更**无从谈起**。plan 只说"几何常数逐字对齐"，**没说
   测量参考路径**。这是**潜在静默 bug**，且正是"观测镜像写错→静默学不动"
   （plan §7 风险表已列）的**最可能触发点**。

3. **§3.2 的"6 维"与 §3.1 声称的"语义对齐"矛盾**已列为 I1；此处补充**它是
   W6–W9 可比性的直接前提**（RQ3 问的就是"只动对手"）。

4. **P2 的"随机对手"语义退化 + 分母未定义**。实测（分层控制下、车不会跑出
   赛道）：纯随机**速度**指令使车**照常前进**（末速 0.251 m/s），随机策略
   1500 步中 **129.7 步**处于碰撞距离；两车对局中 **const vs const 也 50/50
   相撞**、front=const/back=random 时 **16/50 相撞、0/34 取胜**。结论：
   (a) 随机对手**既非惰性、也非稳定弱基线**——它会**乱切车道**
   （`|a_lane|>0.3` 触发换道），语义是"抽风"而非"弱"；
   (b) 由于 **同生共死 + 碰撞**，大量对局以"双亡"结束（"平局不计胜"），
       但 plan 未说 20 局里"双亡"算不算分母——**≥70% 的分母不明**。
   **建议**：改用**结构化弱基线**（如冻结规则对手、或恒定慢速外圈车），
   并明写"胜率 = 胜 / 有效决胜局"。

5. **§1.3 的"镜像语义正确"是误报**。plan §1.3 声称
   `CHECK 3: mirrored obs rows -> approx opposite (镜像语义正确)`。实测
   （同一个 2 行玩具 VecEnv，未训练网络）：
   ```
   identical rows -> actions: [0.22080065 0.22080065]   （对）
   mirrored rows  -> actions: [0.2356026  0.21288042]   （并非 opposite）
   ```
   未训练网络**不是奇函数**，"镜像输入→相反输出"**只在训练后**才可能成立。
   把它写进 §1.3 当"已验证事实"是**过度声称**，会误导 §7 的"镜像自检"
   （该自检若在**训练前**跑，必然失败）。**修订**：自检应验证"**两行同编码
   函数**"（相同 obs → 相同动作，已实测成立），而非"镜像→相反"。
